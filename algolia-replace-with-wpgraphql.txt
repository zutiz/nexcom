     Plan: Replace Algolia search with WooCommerce (WPGraphQL) search

     Context

     Search currently uses Algolia (algoliasearch/lite + react-instantsearch)
     via an external WP indexer plugin (wp-algolia-woo-indexer). The rest of the
     site already talks to WooCommerce through WPGraphQL + Apollo. Algolia is
     used only for the header/mobile/sticky-nav search box dropdown (no results
     page, no facets, no indexing code in the repo), so removal is small and
     self-contained. Goal: search products live from WooCommerce, with no
     Algolia dependency, keys or plugin.

     Approach

     Use WPGraphQL's built-in product search: products(first: N, where: { 
     search: $term }). No WordPress changes are needed (WooGraphQL already
     provides it). Search is MySQL LIKE-based, so it is slower and less
     typo-tolerant than Algolia; mitigate with debounce, min 2 chars, and a
     small first (e.g. 8).

     Steps

     1. Add query SEARCH_PRODUCTS_QUERY to src/utils/gql/GQL_QUERIES.ts. It
        takes $search: String! and $first: Int, and returns databaseId, name, 
        slug, shortDescription, onSale, image{sourceUrl}, plus price, 
        regularPrice, salePrice on the simple/variable product fragments (match
        what FETCH_ALL_PRODUCTS_QUERY already selects).
     2. Add hook src/hooks/useProductSearch.ts:
        - Debounces the input (~300 ms), ignores terms shorter than 2
          characters.
        - Uses Apollo useLazyQuery (or useQuery with skip) with the existing
          client in src/utils/apollo/ApolloClient.ts.
        - Returns { query, setQuery, results, loading }.
     3. Rewrite the UI in src/components/AlgoliaSearch/. Rename the folder to
        ProductSearch/, update imports in Header/Navbar.component.tsx and
        Footer/Stickynav.component.tsx:
        - AlgoliaSearchBox → SearchBox: plain controlled <input> plus dropdown
          list, using useProductSearch. Remove <InstantSearch>, liteClient,
          useSearchBox and <Hits>.
        - MobileSearch: same hook, inline results. Share one component with a
          variant prop to remove the duplicated code.
        - SearchResults → SearchResultItem: takes GraphQL product fields (name,
          image.sourceUrl, price/salePrice/regularPrice, shortDescription). Keep
          formatPrice and trimmedStringToLength. Strip HTML from
          shortDescription.
        - Fix link bug: link to /produkt/${slug}, not the name with spaces
          replaced (this was fragile with Algolia).
        - Keep the Norwegian labels and the existing layout classes.
     4. Optional: add a /sok?q= results page that reuses ProductCard (the
        GraphQL product shape already matches it, so this would be easy). Skip
        unless wanted.
     5. Remove Algolia:
        - npm uninstall algoliasearch react-instantsearch.
        - Delete src/styles/algolia.min.css and its import. Remove the "Fix
          Algolia mobile searchbox" block in src/styles/globals.css (~line 128),
          keeping any rules the new input still needs.
        - Remove the three NEXT_PUBLIC_ALGOLIA_* vars from .env.example and from
          deployment env.
        - Delete plans/algolia-upgrade-plan.md. Update README.md, TODO.md,
          DOCS/repository_context.txt.
     6. WordPress side (outside the repo): deactivate and remove the
        wp-algolia-woo-indexer plugin and revoke the Algolia keys. Optionally
        install a search-relevance plugin (e.g. SearchWP, Relevanssi, or
        ElasticPress/Elasticsearch/Meilisearch) if default WP search quality is
        not enough. WPGraphQL where.search will then use it automatically.

     Critical files

     - src/utils/gql/GQL_QUERIES.ts (add query)
     - src/hooks/useProductSearch.ts (new)
     - src/components/AlgoliaSearch/* → src/components/ProductSearch/*
     - src/components/Header/Navbar.component.tsx,
       src/components/Footer/Stickynav.component.tsx (imports)
     - package.json, .env.example, src/styles/globals.css,
       src/styles/algolia.min.css

     Verification

     - npm run build and tsc --noEmit pass; grep -ri algolia src package.json 
       .env.example returns nothing.
     - npm run dev: type in desktop, mobile and sticky-nav search; confirm
       debounce (one request per pause), a results dropdown, and click-through
       to the correct /produkt/<slug> page.
     - Check empty results, a single-character query, a product with no image,
       and sale-price rendering.
     - Confirm in the network tab that no requests go to algolia.net.
     - Compare search quality (partial words, typos, Norwegian characters)
       against Algolia and decide whether a relevance plugin is needed.
